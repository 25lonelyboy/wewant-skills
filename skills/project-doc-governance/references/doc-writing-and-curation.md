# 文档写作与取舍

当要把结论写进仓库文档、判断某段内容该不该留、或排查"文档越写越脏"时，读取本文件。

## 核心原则

> 每一条内容都要挣得它的位置：不重复、不过期、不留过程。

组织方式（分层、索引、frontmatter）是达成它的手段。本文件回答的是这个原则在**写入时**怎么执行——前三个 reference 管"放哪"，这里管"凭什么这么说、该不该写"。

## 一、取舍判据（段落级）

写入前先判定这段是什么：

| 这段是什么 | 去哪 |
|---|---|
| 稳定结论 | **事实源**（architecture / engineering / product / operations / governance） |
| 过程（怎么试的、当时怎么权衡的） | `docs/tasks/` |
| 中间态、后来作废的 | **直接删**，不写"已废弃"/"曾考虑过" |

一段内容要留在事实源，需满足其一：

1. 会被再次复用
2. 是当前稳定的事实
3. 是某条决策的依据

**三者都不满足就删掉。** 最常见的失败是结论已经结论化了，却把得出结论的过程一并留下——那是你自己需要的东西，不是文档读者需要的。

判据的机械部分由 doc-lint ⑥ 覆盖（终态痕迹词表，含过程阶段引用、过程文档引用、带日期的事件式教训）。剩下的语义判断靠写入时自觉。

技能现有的"该不该记"只做到文档级（见 `official-doc-and-knowledge-policy.md`），而结论活在段落里。这一节是同一个判据下沉到段落粒度。

## 二、更新方式：事实源改写，过程文档追加

这是两类文档最根本的区别，也是"文档随时间变脏"最主要的来源。

| | 过程文档（`docs/tasks/`） | 事实源文档（其余各层） |
|---|---|---|
| 更新方式 | **追加**，不回改历史 | **修改**，只保留与事实匹配的内容 |
| 作废内容 | 追加新节并标注"取代 D1" | **直接改写或删除**，不留旧值 |
| 生长性 | 单向增长（正常） | 应有界；只增不减 = 在积累残渣 |
| 时间语义 | 描述某时发生了什么 | 描述当前是什么 |

推论：

- 事实源文档里的"本次变更为…""此前为…"一律不写。历史由 git 承担。
- 事实源文档应该**有界**。一份只增不减的活文档，无论组织得多整齐，都在积累残渣。超过 400 行是信号（doc-lint ⑨ 以 WARN 提示），该拆或该删。
- 修改事实源时**全局对齐**：改动一条断言后，搜索旧值在其它文档里的出现并同步，不允许"改一处、留三处"。

## 三、单文档结构

读者应该在前几行拿到答案，而不是读完推导过程。

```markdown
---
status: living
scope: code
covers: [路径]
last_verified: YYYY-MM-DD
---

# 标题

> 一句话：本文件管什么、什么时候该读它。覆盖范围：…（不覆盖的一并说明）

## 结论 / 当前事实
（先说结论，再给依据）

## 细节
（可跳读的分节）
```

- **必填开头块**：管什么、何时读、覆盖范围，合计不超过三行。
- **结论先行**：不看细节也能拿到可用结论。
- **不写行号**：引用代码用符号名或路径。`L123` 会被任何一次无关编辑作废，而且不在 `covers` 的检测范围内。（doc-lint ⑦ 会报。）
- **不写过程阶段标记**：`（P5）`、`设计 D5`、`Task 4` 这类记号取自任务目录的上下文，事实源的读者无法解析。（doc-lint ⑥ 会报。）
- **长度**：超过 400 行先考虑拆分，而不是继续堆叠。

## 四、溯源与标注

**沉默不允许**：每条实质断言要么带来源，要么带标注。既无来源也无标注的裸断言视为违规。

这条的价值在于它把"没来源"从**看不出来**变成**看得出来**——如果没有这条规则，核实过的内容和编造的内容在文档里完全同形，读者无从分辨。

### 按断言类型

- **内部事实**（代码、配置、目录结构）：引用真实存在的路径或符号。
- **外部事实**（官方推荐、版本支持、供应商行为、兼容性）：必须带来源与访问日期。
  `[官方文档](URL)，访问于 2026-10-05`
  核不了的不进事实源——留在 `docs/tasks/` 调研笔记里并标注为判断。
- **判断**：明确标为判断，不要伪装成事实。

### 标注与免责散文的区别

必须分清，否则与「只写终态」的纪律互相抵消：一条要求标注不确定，另一条禁止免责声明，界线是——**标注写结论，散文写过程**。

| 允许且要求 | 禁止 |
|---|---|
| `【AI 判断，待验证】` | `本讲不提供 X，因为核实不了` |
| `覆盖范围：仅 P1 阶段` | `以下为假设性框架` |
| `来源：[官方文档](URL)，访问于 2026-10-05` | `样本不足，不外推` |

左列是**状态标签**，告诉读者这条断言的效力；右列是**过程叙述**，靠删掉内容来回避风险。

### 诚实边界

检查器能验证"有没有来源""引用的路径是否存在"，验证不了：

- 是否真的读了那篇网页
- 摘要是否忠实于原文
- 一条断言被归为"事实"还是"判断"分得对不对

这些依赖写入时的自觉。不要把"检测器扫过了"当成内容可靠的证据。

### 规则文本里的禁用词

在规则文档里列举禁用词时，一律写进**反引号**：`修订史`、`已更正`。检查器会忽略行内代码，这就把"定义规则"和"违反规则"区分开了。
