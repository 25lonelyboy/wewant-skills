# 官方文档与经验沉淀策略

更新时间：2026-09-03

当需要为仓库规则、`AGENTS.md` 或文档治理文件编写精确政策时，读取本文件。

## 官方文档查阅规则

凡是任务可能受到版本、平台或供应商推荐影响，优先把官方文档作为决策基线。

### 必须查阅官方文档

- 首次初始化框架、运行时、服务或脚手架。
- 升级主版本。
- 切换关键技术方案或基础设施组件。
- 引入新的基础依赖、服务或平台能力。
- 解决报错、版本冲突、环境问题或行为与预期不一致。
- 用户明确要求按官方、推荐或最新方式处理。

### 可以跳过重复查阅

- 同一会话内刚查过，结论仍然适用。
- 任务只是重复低风险且已验证过的流程。
- 任务只涉及结构清理、文案编辑或其他非技术性维护。

### 解释规则

- 只记录支撑本次决策的最小结论。
- 官方方案与社区惯例冲突时，默认采用官方方案。
- 仓库既有约束要求偏离官方方案时，在变更说明或 ADR 中写明原因。

## AGENTS.md 政策

- **体积预算**：≤150 行（doc-lint 检查项⑤）。超出部分下沉 `docs/` 并在 AGENTS.md 留一行索引链接。
- **只放三类内容**：可直接执行的验证命令（build/test/lint）、硬规则（禁止项与红线）、文档导航与读取顺序。
- **标准验证命令**：`node scripts/doc-lint.js .`（治理工具的仓库副本，初始化/重组时从技能母版落仓库，见 SKILL.md 验收节）。
- **命令可执行性**：写入的命令必须能原样复制执行；禁止“以实际为准”“可以都试一下”之类的模糊表述。
- **安全红线**（覆盖 AGENTS.md 与全部 docs/）：禁止写入密钥、token、账号密码、私有内网地址、客户敏感信息；需要引用时用占位符 `<redacted>`。
- **禁止诱导全量阅读**：不得写“请通读全部文档”类指令；读取顺序必须是按需的索引路径。
- **docs-in-same-commit**：改变已文档化行为的代码变更，必须在同一提交内更新对应文档。

## 经验沉淀规则

只在任务产出可复用知识时更新仓库文档。

### 需要沉淀

- 建立了可复用初始化流程、命令序列、检查清单或脚手架步骤。
- 解决了兼容性、依赖冲突、环境问题或构建验证问题。
- 明确了仓库结构、模块边界、接口契约或团队约定。
- 做出了不可逆或含真实权衡的决策（写成 ADR，见 `adr-governance.md`）。
- 该结论预计后续至少还会复用一次。

### 通常不沉淀

- 一次性改动，无法复用。
- 重复执行已有流程，没有新增结论。
- 只微调既有文档表述。
- 临时绕路方案，没有稳定经验价值。
- 未落地的设计意图（只能写入 tasks/ 的计划文档，不进事实源）。

## 写回位置

- 架构影响 → `docs/architecture/` 的事实源。
- 工程流程、命令、兼容结论 → `docs/engineering/`。
- 业务规则与术语 → `docs/product/`（术语进 `glossary.md`）。
- 运行部署经验 → `docs/operations/`。
- 稳定决策 → `docs/decisions/`（ADR）。
- 文档维护规则 → `docs/governance/`。
- 任务计划、调研、决策过程、验证、复盘 → `docs/tasks/日期-任务名/`。

写回前检查：现有主题文件能否承载？能则补充并更新其 `last_verified`；不能则新建并登记进所在目录 README 索引。

## 可放入 AGENTS.md 的治理规则块

```md
## 文档治理

- 读取顺序：本文件 → docs/README.md → 对应领域 README → 最小主题文件；按需读取，不要求通读。
- 事实源：架构事实在 docs/architecture/，工程实践在 docs/engineering/，决策在 docs/decisions/，过程材料在 docs/tasks/。
- 文档与代码冲突时以代码为准，并修复文档。
- 改变已文档化行为的代码变更，同一提交内更新文档。
- 文档禁止写入密钥、token、内网地址。
- 新文档必须归位到对应层并登记进该目录 README。
```
